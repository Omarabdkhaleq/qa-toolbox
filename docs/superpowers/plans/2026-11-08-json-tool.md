# JSON Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace JSON Editor and JSON Compare with one **JSON** tool: two full editors side by side, in-place structural compare (text, tree, table), auto-sort on Compare, a Changes drawer, a resizable/collapsible split, and Java-style comments that are ignored everywhere meaning is computed.

**Architecture:** A new tool folder `src/tools/json/` composes two `EditorPane`s (today's JSON Editor toolbar, extracted) around a `MiddleMenu`, with a `ChangesDrawer` below. Comments are blanked out (replaced by spaces, newlines kept) inside the shared lossless parser, so the editor library, validation, format and compare all ignore them while positions stay correct. Compare reuses `structuralDiff`; a pure `highlightsFor(changes)` turns changes into per-side path→kind maps that `JsonEditorView` renders as CodeMirror line decorations (text view) and `onClassName` classes (tree/table). Old tools stay registered and green until the last task removes them.

**Tech Stack:** React 19, TypeScript ~6.0, Vite 8, vanilla-jsoneditor 3, CodeMirror 6, lossless-json, jsondiffpatch, json-source-map, Vitest 5, Playwright 1.65.

**Spec:** [`docs/superpowers/specs/2026-11-08-json-tool-design.md`](../specs/2026-11-08-json-tool-design.md) (approved). Project-wide rules: [`CLAUDE.md`](../../../CLAUDE.md), [`intent.md`](../../../intent.md).

## Global Constraints

- Sidebar entry **JSON**, route `/#/tools/json`, tool id `json`. Old routes are **not** redirected (they show "Tool not found").
- Comments: `//` to end of line; `/* … */` (incl. `/** */`), first `*/` ends it, no nesting; markers inside strings are text; escapes in strings respected; unterminated `/*` → parse error at its start with message `Unterminated comment`. Comments are blanked to spaces (newlines kept) so line/column stay correct.
- Format, Minify, Sort keys, Repair, tree/table views and auto-sort **remove** comments; Compare and validation **ignore** them.
- Ticking Compare runs Sort keys on both editors (each with its own indentation); no "Ignore key order" option exists. The Compare checkbox is **disabled while either side is empty or invalid** (a comment-only side counts as empty), with the reason `Paste JSON on both sides to compare` or `Fix the JSON errors to compare`; if a side becomes empty or invalid while Compare is on, Compare turns off and highlights clear. While on, an editor re-sorts **once when it loses focus** (and on whole-document replacements), never while typing.
- Highlight colors: removed = red tint left; added = green tint right; **changed = yellow tint both sides** (light `rgba(255,193,7,.22)`, dark `rgba(255,183,77,.20)`, bar `--changed`: light `#b26a00`, dark `#ffb74d`); moved = `--moved` both sides. Every highlight has a 3px left bar (not color alone).
- At most `10_000` changes highlighted; above that the middle menu shows `Highlighting the first 10,000 of N changes`. Drawer list stays capped at 1,000.
- Split: starts 50/50; snaps a side closed when it would be under 15% of the width; minimum open pane 240 px; double-click or Enter resets to 50; ←/→ step 5%; Home closes left (0), End closes right (100). While a side is closed, Compare controls are disabled. ≤ 720 px: panes stack, handle hidden.
- Theme tokens only (`src/app/styles.css`); text ≥ 4.5:1, non-text UI ≥ 3:1 in light and dark; honor `prefers-reduced-motion`.
- Unchanged project rules (CLAUDE.md): no egress, CSP without `unsafe-eval`, only `src/core/json-view/` imports `vanilla-jsoneditor`, relative imports, coverage ≥ 90 % on `src/core/**/*.ts` + `src/tools/*/logic.ts`, budgets (entry ≤ 150 KB, route ≤ 600 KB gzip; 20 MB open < 3 s; 5 MB compare **including highlight paint** < 3 s).
- **Protected tests:** only the files the user pre-approved in spec §10 may be changed, and only to port them (meaning kept) or to remove the three approved key-order cases; everything else needs a per-case yes. Old tools and their tests must stay green until Task 9.
- Commits: Conventional Commits, message describes only the change — no `Co-Authored-By`, model or tool names.

## Review Focus

1. **`//` and `/*` inside strings** (`"http://x"`, `"a\"//b"`, `"/* not a comment */"`) must stay text — pinned in Task 2.
2. **A document that is only comments** (`// todo`) must show the neutral **Empty** state, not an error — pinned in Task 3.
3. **Big integers through auto-sort** (`{"b":12345678901234567890,"a":1}`) must keep every digit after ticking Compare — pinned in Task 7.
4. **A side with broken JSON** disables Compare (and turns it off if it was on) with the reason `Fix the JSON errors to compare`; the broken text is never rewritten — pinned in Task 7.
5. **Typing while Compare is on** must not re-sort or move the cursor; the editor re-sorts once when it loses focus — pinned in Task 7.

### Task 2: Comment blanking in the shared parser

**Files:** Create `src/core/formats/comments.ts`, `src/core/formats/comments.test.ts`; Modify `src/core/formats/json.ts`; Test additions in `src/core/formats/json.test.ts` (new `describe` block only).

**Interfaces:**
- Produces: `blankComments(text: string): BlankResult` with `type BlankResult = { ok: true; text: string; count: number } | { ok: false; error: ParseError }` (`ParseError` from `formats/types.ts`). `jsonAdapter.parse` and `losslessJsonParser.parse` call it first; `ParseResult` is unchanged.

- [ ] **Step 1: Write failing tests** in `comments.test.ts`:
  - `blankComments('{"a":1} // c')` → `{ ok: true, count: 1, text: '{"a":1}     ' }` (same length; the comment is spaces).
  - block across lines keeps newlines: `blankComments('{/* x\ny */"a":1}')` → `{ ok: true, count: 1, text: '{    \n    "a":1}' }`.

- [ ] **Step 3:** Implement `blankComments` as one left-to-right scan with states *code / string / string-escape / line-comment / block-comment*. Call it in `jsonAdapter.parse` (after `stripBom`, before the empty check) and in `losslessJsonParser.parse` (on unterminated, throw `SyntaxError('Unterminated comment at position N')` so existing position handling applies).
